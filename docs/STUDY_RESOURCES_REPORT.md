## Routes and integration contract

Reuse the established public routes: `/resources` (hub), `/resources/question-papers`, `/resources/learning-materials`, `/resources/video-lessons`, `/resources/temporary`, `/resources/all` and `/resources/item/[id]`. These are the documented equivalents of the requested `/study-resources/*` paths; no duplicate route tree is needed. Existing links continue working. Agent 2 should link to `/resources`; no new dependency, environment variable or migration is required.

Lists accept GET parameters `q`, `subject`, `medium`, `year`, `type`, `source`, `rights`, `chapter`, `marks`. Search retains Tamil Unicode. Facets derive from records in the current category; years/types/sources/rights/chapters/marks narrow after applying subject/medium. Chapter and mark controls are omitted where no evidence exists. Clear filters, empty/loading/error/not-found states remain. A mark filter finds a printed section within a whole source PDF, not an extracted question bank.

`src/lib/study-resources-catalog.json` remains the central version-1 manifest; `study-resource-schema.ts` validates it; `study-resources.ts` exports `studyResources`, `visibleResources`, `resourceSubjects`, `resourceCategories` and `resourceCurriculumReferences`. Existing textbook imports use `tb-<textbook ID>`; the helper references that identity and preserves book ID, subject, medium and volume without creating curriculum rows. References express subject/medium relevance, not exact chapter alignment. `resourceFilterChoices` supplies only evidence-backed choices.

Schema retains stable IDs, class/board, subjects, mediums, year/session/type/chapter, source/landing/direct PDF URLs, check timestamps, append-only provenance, independent availability/authenticity/relevance/rights/redistribution/embedding/editorial status, checksum and local asset permission. New optional `markFormats` defaults to `[]`; each entry requires positive marks, subject, medium, one-based PDF page and evidence. Entries must match resource subject/medium and have a PDF. First recorded date is shown from history; this is not a claim of an earlier undiscovered date. No verified chapter IDs are available; null mappings remain null. YouTube ID is derived from its validated URL, never arbitrary iframe HTML.
